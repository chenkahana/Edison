# Architecture

Edison is one sandboxed macOS app with no dependencies beyond Apple's SDKs and no network code. This document
explains the shape of the code and the rules that keep it reliable. For a file-by-file map, see the
[source tour](../Edison/README.md).

## Process and windows

- Edison runs as an `.accessory` app: a menu-bar item, no Dock icon.
- The **Hub** is a borderless, floating shelf window pinned to the bottom of the active display. It moves to the
  current Space, never becomes the main window, and closes when it loses focus.
- The **editor** and **Settings** are ordinary windows opened by `WindowRouter`.
- Global hotkeys are registered with Carbon `RegisterEventHotKey`, because it works without Accessibility
  permission and doesn't steal key events from other apps.

## State and ownership

`AppState` is the single `ObservableObject` injected into every scene. It owns the services and exposes every user
action, but delegates the work:

| Owner | Responsibility |
|---|---|
| `ClipboardCoordinator` | History mutations, deduplication, history limit, undo-delete, writing items back to the pasteboard, ignoring Edison's own writes |
| `CaptureCoordinator` | Capture requests, screen-recording permission state, editor sessions, committing screenshots to history |
| `PasteBackCoordinator` | Restoring focus to the previous app and sending ⌘V once it is frontmost |
| `HotKeyCenter`, `ShortcutStore` | Registering and persisting global shortcuts |
| `SettingsStore` | Versioned `AppSettings` in `UserDefaults` |

All UI-facing types are `@MainActor`. Pasteboard reads, image processing and disk writes run on serial background
queues; results return to the main actor.

## Clipboard fidelity

Trust comes first: an item must paste back exactly as it was copied.

- `ClipboardMonitor` polls `NSPasteboard.changeCount` and, on a change, reads the declared types in order. Plain
  text is always kept as the canonical `String`; RTF, RTFD and HTML (the only rich types allow-listed) are stored as
  opaque bytes in size-limited, SHA-256-checked sidecar files (`ClipboardRepresentationStore`).
- Items marked `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` are never stored. While
  history is paused, changes are acknowledged and dropped.
- **Paste** recreates one pasteboard item with every preserved representation, so the destination app picks its
  preferred type. **Paste as Plain Text** writes only the exact plain string.
- No stored text is ever trimmed, normalized or re-wrapped. Display transformations (link hosts, colour swatches,
  code previews, Markdown rendering) happen in the UI layer only; `ClipboardContentKind` classifies, it never
  rewrites.

## Persistence

Everything lives in the app's sandbox container under `Application Support/Edison`:

| Data | Store | Format |
|---|---|---|
| History and collections | `HistoryStore` | `history.json`, written atomically off the main thread |
| Rich text | `ClipboardRepresentationStore` | One sidecar file per representation, reconciled at startup |
| Images and screenshots | `ImageStore` | PNG plus thumbnail, referenced by relative path |
| Settings and shortcuts | `SettingsStore`, `ShortcutStore` | `UserDefaults` |
| Previews and drag-out | `TemporaryFiles` | Owner-only temporary folder, cleared on close and at launch |

Deleting an item (once its undo window passes) or evicting it past the history limit deletes its image and sidecar
files too. Legacy history formats decode and migrate transparently.

## Capture and annotation

- `CaptureEngine` uses ScreenCaptureKit (`SCScreenshotManager`) for area, window and display captures. Area
  selection draws one overlay window per display, so selections work on any monitor.
- A capture becomes a `ScreenshotSession`: the original image plus a stack of `ScreenshotDocumentSnapshot`s
  (crop rect and annotations), which gives undo and redo for free.
- Annotations are stored in image coordinates (points, bottom-left origin). `ScreenshotAnnotationRenderer` draws
  them into any `CGContext`; the editor canvas uses it through `Canvas.withCGContext`, and export uses it into a
  bitmap at the image's pixel scale. One renderer means the preview is the export.
- Pixelation draws a cached, fully pixelated copy of the base image clipped to each redaction rect, so the
  original pixels under a redaction never reach the exported PNG.

## Hub interaction

- Keyboard events reach a first-responder bridge view (`HubWindowAccessor`) before SwiftUI, so arrows, Return,
  ⌘-numbers and type-to-search work without focusing a text field.
- Search (`HistorySearchEngine`) is a pure function over the history: all words must match, with `app:` and
  `type:` tokens, composed with the type filter, favourites and the selected collection.

## Principles

- Prefer direct code over abstraction; add a layer only when the current code blocks delivery.
- Local-only. No sync, accounts or network calls without a separate, threat-modelled proposal.
- Accessibility and keyboard access are part of every feature, not polish.
