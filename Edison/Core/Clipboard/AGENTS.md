# Clipboard

## Purpose
Monitors the system clipboard for changes and converts raw pasteboard contents into typed `ClipboardItem` values. Also provides image optimisation utilities used by both clipboard monitoring and the capture pipeline.

## Key Files

| File | Description |
|------|-------------|
| `ClipboardMonitor.swift` | Polls `NSPasteboard` every 0.6 s via `Timer`; skips transient, concealed, and auto-generated pasteboard types; dispatches new `ClipboardItem` values to the main thread via a callback |
| `ImageProcessing.swift` | `ImageProcessing.prepareImagePayload(from:)` — resizes images to max 2200px, generates a 200px thumbnail, returns a `ClipboardImageData` with both as PNG |

## For AI Agents

### Working In This Directory
- `ClipboardMonitor` is **not** `@MainActor` — pasteboard processing runs on `processingQueue` (serial `.utility`). Only the callback dispatch back to main is explicit.
- Three pasteboard marker types are silently skipped: `org.nspasteboard.TransientType`, `org.nspasteboard.ConcealedType`, `org.nspasteboard.AutoGeneratedType`. Respect this to avoid polluting history with password manager or auto-generated content.
- A wake observer (`NSWorkspace.didWakeNotification`) re-checks the pasteboard after sleep, because timers pause during sleep.
- `ImageProcessing` is a caseless `enum` used as a namespace — `prepareImagePayload(from:)` is `nonisolated static` so it can be called from any context.
- If adding a new payload type, update `makeClipboardItem(from:sourceApplication:)` in the correct priority order (text → image → fileURL).

### Testing Requirements
- `shouldSkipStorage(for:)` is `internal` — covered by tests in `Tests/EdisonTests.swift`.
- `prepareImagePayload` requires a valid PNG/TIFF input and returns `nil` for corrupt data — test both paths.

### Common Patterns
- `ClipboardMonitor` is initialised with a default `sourceApplicationProvider` closure that reads `NSWorkspace.shared.frontmostApplication`; tests can inject a custom provider.
